# Verifier qualification implementation checkpoint

9 October 2026, Australia/Sydney. Continuation of NB-003/004; human code-security review pending.

The trusted Node controller owns three identity-function cases and their comparisons. Each case starts a fresh pinned Linux Node container. Candidate code runs only there. Checks stay on the controller; candidate stdout is bounded untrusted JSON data, compared with the expected value. Successful exit alone cannot pass. Source and policy hashes are separate. This synthetic identity function is a boundary probe, not implementation of the taskboard story.

Containers receive only a newly staged read-only synthetic source directory. No repository, home, provider credential, application configuration or Docker socket is mounted. Network is disabled; root is read-only; UID/GID are 65534; capabilities are dropped and new privileges disabled. Memory/swap, CPU, process count, temporary storage, client output and wall time are bounded. The controller removes every named container and checks daemon inventory before proceeding. Cleanup failures abort qualification. This is daemon-observed container removal, not independent kernel attestation. Controller crash recovery and ownership-ledger integration remain outstanding.

Thirteen variants each run against three cases: correct data, wrong data, exit-zero bypass, forged success output, output flood, CPU runaway, child/grandchild runaway, source write, absent checks, absent host path, absent socket, direct-IP network and environment/security flags. All individual case outcomes must match expectations. Container errors are recorded separately; negative failures alone cannot establish isolation, so positive controls are mandatory. The path probes cover specific synthetic paths, not exhaustive filesystem analysis. No host-secret file contents or candidate stderr/stdout are retained in evidence.

This checkpoint does not consume source capsules or task approvals, authorize retries, qualify a coding provider, or enable task execution. Capsule tamper tests remain in the earlier component suite; composition with this runner is pending. Synthetic temporary staging remains until CI runner disposal. No generated source executes on the Windows host. Qualification is restricted to the selected disposable GitHub Linux runner.

Implementation references: [Docker run controls](https://docs.docker.com/engine/containers/run/), [forced container removal](https://docs.docker.com/reference/cli/docker/container/rm/), and [Node child process bounds](https://nodejs.org/docs/latest-v24.x/api/child_process.html). Runtime results must be reviewed before any passing qualification claim. Broader secret-canary attacks, memory/PID/storage exhaustion, cancellation/controller-crash recovery, trusted capsule consumption and production operations remain required.
